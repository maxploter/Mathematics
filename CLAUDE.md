# CLAUDE.md

Rules for agents working in this repo. See `README.md` for what the repo is.

## Don't decide the next action mid-session

`NEXT.md` exists so Maksim never opens this repo and has to think about what to do. If asked to
help "do math tonight," read `NEXT.md` and `curriculum.md` first — don't propose a new topic or
ask what he wants to work on. At the end of the session, rewrite `NEXT.md` yourself with the
next concrete action (exact file, exact next step), not a vague pointer like "continue lecture."

## Track discipline

Don't merge the two tracks or let top-down casually restart syllabus material, and don't let
bottom-up wander into project-building. If a top-down unit turns out to need a foundational
concept bottom-up hasn't reached yet, borrow it inline (a paragraph, a formula) rather than
pausing to teach the full topic — the point of top-down is momentum toward an artifact.

## Don't invent progress that isn't verified

The pre-existing course folders (probability, linear algebra, stats, etc.) were gathered over
~2025-06 to 2026-04 with no visible notes on what was actually completed — assignment PDFs are
present but their solved/unsolved state hasn't been checked file-by-file. Don't assume an
assignment is done because the PDF exists. When resuming a track, say plainly that completion
status is unverified and the first step is to check, rather than asserting a place in the
syllabus.

## Review trigger

After 8 combined sessions or 4 weeks from module creation (see `curriculum.md` for the date),
stop and reassess before continuing on autopilot: is the two-track split working, is the
4x/week cadence realistic, is the artifact format for top-down actually happening or becoming a
tax. Do not let a starting configuration become permanent by default — see
`health-fitness/docs/coaching-rules.md` in the root KnowledgeNexus workspace for why this
matters (a narrow starter program silently became the permanent one there).

## Sharing

Never push Maksim to publish. If a top-down unit produces something genuinely shareable, it's
fine to note that in the unit's own notes, but the channel and the decision to post at all are
his call each time, based on the specific content — not a schedule this repo enforces.
